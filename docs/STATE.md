## Decisions
- DECISION (2026-07-28, founder): the @username rule wins **even inside a shared community** — being in the same club does NOT grant the right to DM. Implemented in 0078; the community roster's one-tap "Message" buttons were removed and replaced with the member's `@handle`, so a lead looks them up instead of cold-messaging. Why: the constraint is about unsolicited contact, and a roster is exactly where cold contact would start.
- DECISION (2026-07-28, founder): **do NOT lock down the `profiles` SELECT policy** — measured, not assumed. Applying a self+shared-context policy inside a rolled-back transaction gave: profiles visible 18 → **1**, findable by partial name 16 → **1** (goal met), but **listings with a resolvable seller name → 0** and **board posts with a resolvable author → 0**. Not degraded — zero. RLS cannot distinguish "look up the one id I am already allowed to see" from "scan the table with ilike"; both are SELECT, so blocking the scan blocks the join that renders "sold by Chiru". Since 0078 already blocks the actual harm (unsolicited contact), what remains is that a determined person with devtools can *see* a list of names at their own college — a privacy nuisance, not a contact vector, and the unavoidable price of showing a seller's name on a listing at all. **If this is ever revisited, the only non-breaking route is moving every name lookup to definer RPCs across listings/board/chat/karma × 3 forks — a phase, not a patch.**
- DECISION (2026-07-27, closes QUEUE A11): **won't-do fuzzy venue→building matching** for the Phase 5d events overlay. Events carry a free-text `posts.location` ("SJT Auditorium", "Room 214, K Block"); resolving that to a `campus_buildings` row by name similarity guesses, and a confidently-wrong pin is worse than no pin — the same reasoning that makes `coords_verified` default false. Replacement, which is strictly better and deterministic: the event organiser PICKS the building (they know the venue), and the event links to Compass focused on it. Half of that shipped today — Compass now honours `/?b=<building id>`, flying to the pin and opening its sheet. The remaining half (a `posts.building_id` FK + a picker on the event form + the link on the event page) is filed as QUEUE A34.
